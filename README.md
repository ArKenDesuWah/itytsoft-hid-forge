# ⌨️ itytsoft-hid-forge (`set_key.py`)

本專案是一個專門針對 **itytsoft 全系列自訂小鍵盤 (支援 1-Key 及未來多鍵擴充)** 所開發的高級硬體刷寫工具。本工具透過**完全解密該廠牌晶片獨有的「動態線性排隊與對齊插槽規律」**，實現了任意長度組合鍵、獨立左右修飾鍵的動態盲刷固化。

> ⚠️ **專用硬體聲明**：本工具採用的 `0xF1`～`0xF8` 晶片轉譯碼及 `[Key, 0x00, 0x00]` 線性插槽協定，為 itytsoft 廠牌晶片特有的非標準 HID 設計，市面上其他標準開源小鍵盤（如 QMK/VIAL 架構）並不適用。

## ✨ 核心優化特點

* **全系列硬體相容**：架構具備高度擴充性，原生支援 1-Key 超迷你硬體，並完美預留多按鍵矩陣配置。
* **動態線性排隊 (Dynamic Key Chain)**：擺脫固定 `mode` 限制，依據輸入按鍵數動態調整總鍵數，並以 `[Keycode, 0x00, 0x00]` 插槽矩陣動態展開。
* **解鎖隱藏晶片碼**：突破官方限制，100% 透過實測數據解鎖右側修飾鍵（`RCTRL 0xF5`、`RSHIFT 0xF6`、`RALT 0xF7`、`RWIN 0xF8`），支援極客級的混搭組合。
* **Fail-Fast 硬體攔截**：每次輸入前自動偵測 USB HID 連線狀態，未連線即時提示，拒絕無效輸入。
* **高流暢互動 UI**：優化使用者體驗，改鍵 Layer 於程式啟動時「只選一次」，後續即可專注批次刷寫；Log 日誌高度降噪，單行完美呈現文字與晶片碼對照。
* **極致切片對齊與性能**：捨棄複雜的 `if/else` 長度判斷，利用 Python 切片技術完美對齊 65 位元組硬體封包；將 Commit 指令靜態化，零記憶體浪費。

## 🛠️ 硬體通訊協定架構

發送至小鍵盤的 `packet`（基礎 65 位元組，Windows 環境下補 `0x00` 穿透對齊至 66 位元組）結構如下：

### 1. 配置封包 (Packet) 矩陣
* **前導標頭 (6 Bytes)**：`[0x03, 0xFD, 0x01, layer_idx, 0x01, 0x00]`
* **核心排隊區**：
  * 第 7 位元組：`total_keys` (參與組合鍵的總按鍵數)
  * 第 8~9 位元組：`[0x00, 0x00]` (標頭間隔碼)
  * 後續動態展開：修飾鍵（左側先排，右側緊跟）在前方排隊，主按鍵殿後。每個按鍵後方固定補兩個 `0x00` 隔開。
* **尾隨填充**：使用數學切片自動補 `0x00` 直到精確對齊 65 位元組。

### 2. 修飾鍵動態排隊碼對照表 (實測確認)
晶片內部針對多組合鍵設計了完美的線性平移編碼：
* **左側/通用**：`CTRL(0xF1)`、`SHIFT(0xF2)`、`ALT(0xF3)`、`WIN/LGUI(0xF4)`
* **右側獨立**：`RCTRL(0xF5)`、`RSHIFT(0xF6)`、`RALT(0xF7)`、`RWIN/RGUI(0xF8)`

## 🚀 快速上手

本專案全面採用新世代高速 Python 套件管理器 **`uv`** 來管理環境。

### 1. 環境準備
使用 `uv` 快速建立虛擬環境並安裝系統專用的 `hid` 驱动库：
```bash
# 建立虛擬環境並同步安裝依賴
uv venv
uv pip install hidapi
```

### 2. 執行指令
在虛擬環境中啟動改鍵工具：
```bash
uv run set_key.py
```

## 📂 核心原始碼結構說明

* `parse_input_string(input_str)`: 
  **單一資料源設計**。負責將字串依 `+` 分解，同時查表產生 `key_chain` (Hex 碼鏈表) 與 `text_chain` (文字鏈表) 並成對回傳。拒絕重複反向查表，效率極高。
* `burn_to_device(path, key_chain, layers)`: 
  核心硬體寫入函數。利用動態循環與 `(packet_data + [0x00] * 65)[:65]` 高階切片技術，完美將動態鏈表打包成晶片指定的插槽矩陣，並完成 65/66 雙長度盲刷與靜態 `Commit` 固化。
* `main()`: 
  主控制迴圈。整合最上層的 Fail-Fast硬體連線檢查、極簡化降噪 Log 輸出，提供絲滑的改鍵體驗。

## ⚠️ 注意事項
1. **單鍵模式**：若要將某個鍵單純對應為獨立修飾鍵（如只當作左 Ctrl 鍵），請輸入 `LCTRL`（對應標準 HID 碼 `0xE0`），此時晶片會自動跳過組合鍵排隊區，走標準單鍵發送。
2. **FN 鍵限制**：由於 `FN` 鍵為鍵盤內部硬體層切換開關，不參與 USB HID 協定傳輸，因此本系統與官方軟體相同，不支援將 `FN` 鍵寫入組合鍵排隊區。
